# 前端科技感与全组件动效升级方案

研究日期：2026-10-18。对象：当前工作区的 Agentic Usage Hub 原生 HTML / CSS / ES Modules 前端。

实施记录见[上一轮报告](FRONTEND_TECH_MOTION_IMPLEMENTATION.md)；用户反馈后取消了会影响滚动区域的平移，并增强了实际操作时的可见反馈，当前行为以[动效与滚动条修复记录](FRONTEND_MOTION_SCROLL_FIX.md)为准。下文保留研究阶段的方案原文与当时的交付边界。

建议采用「智能体遥测控制台」风格：深蓝黑表面、青蓝光线、细网格、清晰的数字层级，并让数据读取、数值变化和功能切换形成连续反馈。实时页承担最明显的动态表现，趋势页突出数据联动，项目页突出空间重排，画廊突出作品浏览。

本文是可拆分实施的设计与工程方案，包含 **100 个组件与交互点**。表中的颜色、时长、阈值、资源预算、优先级和工期均为本项目建议，不是引用项目的原样配置，也不代表已经实施或测得。

## 3. 视觉与节奏规范

### 空间与光感

| 层级 | 建议表现 | 使用位置 |
| --- | --- | --- |
| 环境层 | 深蓝黑底 `#080D17`，48px 细网格，低对比角落光晕 | 页面背景；浅色主题使用淡蓝灰网格 |
| 表面层 | 卡片 `#101A29`，内层 `#0C1422`，1px 边框，顶部窄高光 | 所有数据面板；长表格保持平整 |
| 操作层 | 青色 `#58D8F5` 与蓝色 `#6F9BFF`，局部聚光，按压回弹 | 选中控件、可点击卡片、主要入口 |
| 数据层 | 等宽与等宽数字、固定小数/单位、变更短提示、真实数据曲线 | KPI、实时读数、占比与排名 |
| 强调层 | 单次边缘扫描、真实事件脉冲、灯箱空间过渡 | 刷新完成、新用量、新图片、作品打开 |

厂商曲线颜色延续识别用途；错误、警告、成功仍有文字和图标，不与品牌装饰共用含义。浅色主题采用深蓝线条、轻边缘高光和实体表面，单独校准对比度。

默认不使用全屏粒子、持续故障闪烁、数字乱码或大幅 3D 倾斜。科技感主要由材质、精细光线和数据交互建立。画廊可以比分析表格使用更明显的空间动画。

### 建议的动效等级

新增设置「动效：完整 / 轻量 / 关闭」，默认完整，并始终尊重系统减少动画偏好。轻量保留操作和状态反馈，关闭背景漂移、指针光感、倾斜及密集错峰；关闭模式直接提交最终界面。减少动画时使用静态状态文字和轮廓反馈。

| 事件类别 | 时长 | 位移 / 其他限制 |
| --- | --- | --- |
| 按压、勾选、焦点反馈 | 90–140ms | 按钮缩放最低 0.98，不移动点击区域 |
| 页签、筛选、短列表更新 | 160–220ms | 4–8px，连续操作从当前视觉状态接续 |
| 抽屉、详情、灯箱 | 220–320ms；退出 140–180ms | 抽屉 24–32px；退出更短 |
| 数字、真实占比条 | 240–400ms | 1 秒轮询的数字控制在 180–240ms |
| 首次分组入场 | 220–300ms，组间 30–45ms | 首屏最多 6–8 项，总延迟不超过 180ms |
| 氛围漂移 | 18–26s / 周期 | 最多两个光层，约 12px，后台及离屏停止 |

基础缓动延续 `cubic-bezier(.22,1,.36,1)`。退出使用较短 ease-in；弹性仅限小型操作反馈，图表与金额避免明显过冲。

## 5. 四条最能体现科技感的操作路径

### 实时监控：让真实新用量成为视觉事件

进入实时页 → 控件与 KPI 分组显现 → 首次读取直接显示有效数值 → 新采样到来时仅更新变化读数 → 对应会话行一次短提示 → 有真实新图片时图像计数强调。

本轮响应若没有新用量，就只更新检查时间。暂停、空闲和缺日志是可辨认的静态状态。页面无需为了显得忙碌而不断重画。

### 趋势筛选：让变化有清楚的顺序

点击来源 / 日期 → 选中底板立即响应 → 摘要注明当前条件与读取状态 → 最新有效响应提交 → KPI、份额、排名同帧更新 → 主图按口径选择补间或淡化。

切金额与 Token 时，单位马上明确，曲线不做跨量纲数值补间。筛选请求的有效性仍由已有请求序号和取消机制决定，不能由动画结束时间决定。

### 项目排序：让用户跟得上卡片去了哪里

选择排序 → 记录当前可见位置 → 稳定项目节点重排 → 220ms 内移动到新位置 → 排名与份额一起更新。展开某卡片时，只让受影响的相邻卡片让位；复制路径只反馈当前按钮。

### 作品浏览：让缩略图和大图有空间联系

图片读取完成 → 缩略图淡入 → 点击缩略图 → 大图从原位置展开 → 按方向切图 → 关闭回到仍可见的原图。搜索或翻页导致原卡片不在视口时，以淡出完成关闭。

### 在现有 helpers 上扩展

建议扩展现有能力，而不是再注册一套同名全局动画系统：

```js
// 设计接口示意，尚未实施。
animateValue(id, value, formatter, { duration: 220, reason: 'poll' });
animateView(panel, { direction: 1, reason: 'navigation' });
reconcileCards(container, cards, { enter: true, exit: true, reason: 'sort' });
```

集中增加少量内部能力：

- `getMotionPolicy()`：合并用户等级、系统减少动画、页面可见性及效果类别。
- `replaceAnimation(element, channel, keyframes, options)`：按元素与用途取消旧动画，从当前视觉状态衔接。
- `highlightChange(element)`：只在值变化时执行；轮询无变化不执行。
- `revealGroup(container)`：只对首见且在视口的少数项目播放；内容立即可访问。
- `disposeMotion(scope)`：换页、关弹层、用户关闭动效、页面隐藏时取消相关任务。

这些名称是接口建议，实施时可根据 `experience.js` 现有结构调整，不要求每个名称都形成独立导出。

### 需要先处理的几个实现细节

1. **保留数字与填充层节点。** 仅复用外层卡片但替换 `innerHTML`，仍会丢失数字的 WeakMap 状态、图片加载状态、输入焦点以及条形图补间。项目卡片的静态结构与数据更新应分开。
2. **按业务身份匹配。** 工程用完整身份 ID，图片用文件身份，会话用 sessionId，额度窗口用来源内稳定窗口标识，模型族用族键，日表用日期。新旧曲线用稳定系列键。
3. **布局测量批量执行。** 先收集所有旧位置，再更新 DOM，最后统一读取新位置并播放。避免为每一行反复交错读写布局。大表只动画可见行。
4. **不同动画使用不同层。** 卡片外层负责 FLIP，内层负责 hover，伪元素负责光线；灯箱图像的拖动与打开动画有明确交接，避免同时覆盖 transform。
5. **动画可以取消，数据不能等待。** DOM 状态和 aria 属性在操作成立时更新；动画仅呈现变化。过期响应、关闭后图片 onload、快速主题切换和筛选都不能提交旧结果。
6. **退出项不妨碍交互。** 短暂保留的退出视觉层设置不可聚焦、不可点击并从辅助技术中隐藏；完成或取消后删除。优先采用简单整组淡化，避免复杂 ghost 节点造成维护负担。
7. **跨单位 / 跨集合切换独立处理。** 金额与 Token、来源与模型、线性与对数不能不加判断地共用数值 morph；优先短淡化。相同序列和量纲的更新再做插值。
8. **浏览器能力渐进增强。** `document.startViewTransition`、复杂 mask 等能力先检测；优先支持现有 CSS / WAAPI 路径。动效关闭后业务功能完整可用。
9. **继续本地离线运行。** 光线、网格和小图用 CSS / SVG；不使用运行时 CDN 字体、脚本或远程动画资源。若增加库，固定版本并随包提供本地文件。
10. **尊重现有无障碍交互。** 保留 tablist 键盘导航、焦点陷阱、inert、Esc 与焦点恢复；计数动画不给 aria-live 每帧播报，最终值另行更新。

## 7. 性能与验收目标

以下是实施后的验证目标，尚未进行新动效的性能测量。

| 场景 | 验收方式与目标 |
| --- | --- |
| 首屏 | 数据可用时立即可读；不等待 Logo、标题或卡片动画；图表 / 图片区域预留高度 |
| 标准操作 | 选中 / 按压反馈尽快出现；一次筛选的主要过渡约 300ms 内完成，额外网络时间单独显示 |
| 静止页面 | 除完整模式最多两个 CSS 环境光层外，不常驻运行装饰 rAF；轻量和关闭模式无氛围循环 |
| 后台与离页 | 实时请求沿用现有暂停机制；新增 rAF、WAAPI、监听器与观察器正确清理；恢复无补播 |
| 实时 1 秒档 | 动画不跨越下一次更新；无变更响应不触发读数/行提示；持续 60 秒确认会话 DOM 不反复整体重建 |
| 渲染 | 优先 transform / opacity；对真实高度展开、比例宽度与渐变绘制单独抓性能记录；没有新增动画导致的持续长任务 |
| 大列表 | 当前分页机制继续有效；重排只覆盖可见元素，最多 8 项首展错峰；不为每个卡片注册全局 pointermove |
| 图表 | 实例与隐藏系列保留；金额 / Token 口径无误；缺日与未知值语义不变；主题变化不重播数据 |
| 设备 | 桌面与触摸设备分别验收；320 / 390 / 768 / 1440px、浅色 / 深色均无整页溢出 |
| 动效偏好 | 页面打开期间切换系统减少动画和用户等级均立即生效；CSS、WAAPI、rAF、Chart.js、View Transition 同时受控 |
| 交互 | 连续快速切视图 / 来源 / 日期、开合详情、Esc 关闭后立即重开、灯箱加载中换图，都以最后意图为准 |
| 数据真实性 | 不生成假用量、不推算未知图像 Token、不把等待时间画成生图百分比、不用装饰动画表示进程状态 |

现有 `npm run test:ui` 已覆盖响应式、键盘、图表连续性、分页、弹层、灯箱、请求、实时控制和减少动画。实施时优先扩展这些有业务意义的检查，不为每个视觉 easing 单独写快照测试。新增重点应是：快速中断、节点身份、后台零任务、偏好实时切换，以及仅真实变化才提示。

## 8. 建议实施顺序

| 批次 | 具体产物 | 建议完成条件 | 粗估工作量 |
| --- | --- | --- | --- |
| 第一批：统一科技感与动效基础 | 明暗材质 / 网格、按钮与浮层、动效等级、事件与取消机制、刷新与加载状态 | 五视图切换、减少动画和后台策略一致；已有交互回归通过 | 1–2 人日 |
| 第二批：实时页与趋势页 | 实时差异读数 / 会话、采样小图、筛选联动、图表事件策略、KPI 与排名 | 看得见真实变化且没有假实时；1 秒刷新和快速筛选稳定 | 2–3 人日 |
| 第三批：项目、今日与业务弹层 | 节点保留、重排 / 展开、额度与预算、来源诊断和导出反馈 | 排序可跟踪，详情状态不丢，统计口径保持准确 | 2–3 人日 |
| 第四批：画廊表现与精修 | 图片就绪淡入、方向切图、关闭回原位、可选聚光与倾斜 | 大图 / 小图、触摸 / 键盘、加载失败与快速切图通过验证 | 1–2 人日 |

上述为单人实现加常规验证的粗估，取决于已有 DOM 更新方式需要拆分的程度。优先完成第一批及第二批核心项，再逐步加入 P2 效果；不需要等待全部 100 项完成才呈现收益。

最先落地的六项建议是：**环境与卡片光感、统一动效等级、筛选与导航联动、实时会话差异更新、图表按事件选择过渡、画廊打开与返回。** 它们覆盖首屏、主操作、数据变化和作品浏览，能建立最清楚的整体风格。
