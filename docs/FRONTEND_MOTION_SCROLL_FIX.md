# 加载滚动条与动效修复

日期：2026-10-18。对应反馈：动效难以察觉，加载和刷新时横、纵滚动条不断变化。

## 原因与修正

- 复现时，1440px 视口的整页 `scrollWidth` 在一次刷新期间从 1440px 增大到约 1725px；390px 视口增大到约 480px。加载光条使用 `scaleX` 和 `translateX`，绝对定位的伪元素移出了导航范围。经典滚动条出现后会进一步挤压内容并改变换行。
- 光条现在只动画 `background-position`，2px 高的几何边界保持不变。按钮加载旋转与成功着色保留；成功勾号原来插入正常文档流，现在改为不占空间的边框、颜色反馈，刷新文字预留固定宽度。
- 背景光晕放入固定、裁切、隔离的装饰层，移除持续平移。退出卡片的临时副本也放入独立裁切层，并在退出结束后移除空层。
- 页面过渡移除整块内容平移。完整模式每次切页都会播放 420ms 卡片显现，最多 220ms 错峰；卡片从最终尺寸内部缩放进入。选中滑块延长到 320ms，分页和排序使用局部显现，刷新相同内容不会重播入场。
- 修正工程、画廊摘要和趋势面板的动效选择器，使其匹配项目实际使用的组件类名；父面板与内部标题不再叠加入场动画。请求明细翻页也改为原位显现。
- 页面保留滚动条槽位；时间戳和刷新文字预留宽度；图表 Canvas 在初始化前也受父容器宽度约束；长状态说明在单行中省略，完整内容可通过悬停查看。
- 选中滑块使用布局坐标测量，避免读到卡片动画中的缩放尺寸。系统减少动态效果和用户关闭设置继续有效。

## 验证方式

新增 `loading and refresh scroll stability` 浏览器回归：

- 320 / 390 / 768 / 1440px，640px 高度下记录慢速首载。
- 上述四个宽度 × 明暗两主题 × 五个视图，共 40 个保持相同数据的刷新场景；每次滚动到页面中部后触发刷新。
- 每个动画帧记录整页滚动宽度、高度、横纵滚动位置、刷新按钮宽度和导航位置。刷新期间这些数值须保持稳定，容差 1px；首载允许真实内容到达后增加高度，但任何帧均不得横向溢出。
- 额外确认再次进入已访问的页面时仍有分批卡片动效，且不平移整个内容区。

```powershell
npm run test:motion -- --check "loading and refresh scroll stability" --artifacts output/frontend-motion/scroll-fix
```

验证使用隔离 API 夹具与 Chromium；首载后内容由占位状态变为真实数据，页面高度允许随内容改变。逐帧刷新断言针对数据不变的场景，真实数据新增行时的合理内容增长不应被禁止。

## 最终结果

- `npm run test:ui`：25 / 25 组通过。
- `npm run test:motion -- --artifacts output/frontend-motion/scroll-fix/final --capture`：14 / 14 组检查通过，0 失败；报告另含原生中间帧与视觉输出两个结果组。
- 新增稳定性检查共 44 个场景（4 个首载、40 个刷新）、4907 帧。相同数据刷新期间，整页宽高、横纵滚动位置、按钮宽度和导航位置的观测变化均为 **0px**。
- 60 秒动态用量更新检查通过；会话节点始终 89 个，稳定后 JS 动画、数字帧与指针帧任务均为 0。
- 前端模块语法检查通过；输出 21 张截图及新版动效录屏，未捕获页面脚本异常。
