## 2026-11-19 来源与历史口径复核

- 业务 API 对本机配置工程的日志尾部进行了只读抽样：21 份文件中 6 份含用量，按请求身份去重后 599 条记录，Token 分项守恒，0 解析错误。部分旧记录缺缓存拆分，仍为金额估算。未把原始路径、请求 ID、提示词或回复写入公共夹具。
- Codex 当前已安装 CLI 为 `0.164.0-alpha.11.1`。真实会话元数据与 ccusage 20.0.51 的输入/缓存/输出合计一致。核对只覆盖抽样主会话，不扩大为全量历史准确性承诺。
- 3 份 Claude 兼容网关样本缺少 requestId，使用非 Anthropic 格式的消息 ID；直接账本与原始 ccusage 合计存在差异，保留了反证记录。核对 [ccusage v20.0.51 的身份匹配实现](https://github.com/ccusage/ccusage/blob/v20.0.51/rust/adapters/claude/src/lib.rs) 后确认：上游在这类输入中将时间戳纳入身份，样本中的重复快照逐条计入；本项目按会话消息 ID 取完整快照。差异已定位为身份规则，不能宣称这些样本与上游完全一致。诊断与导出现在保留该身份假设；网关跨请求复用同一个消息 ID 时仍无法精确核对。
- 补充 requestId + messageId 的区分，防止不同请求使用相同消息 ID 时被合并；未提供请求 ID 的日志继续使用已有会话消息规则。另修复日志显式报告 0 美元被误当未知，以及仅有 5 分钟/1 小时缓存写入拆分时遗漏 Token 的问题。
- 手动执行本机已登录 CLI 的 `account/rateLimits/read` 成功，读取到 300 分钟桶；没有创建模型对话，也没有将额度数值或身份信息写入公共报告。
- 新增跨进程变更/禁用审批估算模型的恢复回归，修复“recorded”金额被配置变化重新捕获、保存金额与显示估算模型不一致的问题；“current”按所选快照的费率与假设重算。
