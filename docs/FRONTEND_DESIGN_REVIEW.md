# Agentic Usage Hub 前端视觉与动效优化分析

分析日期：2026-10-13。依据优化前的工作区代码、运行在 `127.0.0.1:4242` 的页面，以及官方设计资料。浏览器检查了 1440px 桌面深色/浅色、Today、Projects 和 390px 手机 Timeline。另由 subagent 独立完成静态代码审查。以下问题与建议已落实到业务页面，见[实施与验证记录](FRONTEND_OPTIMIZATION_IMPLEMENTATION.md)。

## 建议方向

采用精致、克制的开发者分析工具风格：清晰的信息层级、统一的中性色表面、少量强调色、连贯的数据更新和详情展开动画。

目前项目已有双主题、玻璃表面、卡片 hover、缩略图缩放、弹窗入场、状态点脉冲、焦点样式和 CSS 减少动画适配。最有价值的升级是把这些孤立反馈连接成一套完整交互。

## 优先优化的页面问题

### 1. 首屏信息层级与筛选位置

桌面 Timeline 当前在图表之前排列品牌、主题与计价控件、主导航、长口径提示、九个来源入口、生图入口和四张 KPI。1440×1000 首屏中主图仅开始露出，日期筛选还位于 KPI 下方。

建议顺序：页面导航 → 标题与日期范围 → 核心指标 → 主图 → 来源/模型构成 → 明细。日期应先于所影响的 KPI，让用户直接理解统计范围。保留简短的“API 等值估算”说明，并提供完整口径提示；计价设置仍应能被找到。

主导航短名使用“今日 / 趋势 / 项目 / 画廊”。统一线性 SVG 图标；目前 emoji 与 SVG 混排，各系统渲染差异较大。主题与 ZCode 计价可进入设置入口，对数刻度、自定义纵轴上限收进图表设置。

依据：`public/index.html:45`、`:95`、`:378`、`:495`。

### 2. 手机溢出应先修复

390px 手机 Timeline 实测 `document.documentElement.scrollWidth = 974`。厂商筛选 `.agent-tabs` 宽约 950px，截图中后面的来源被截断；这不是仅凭代码推断的问题。

建议将来源选择变为容器内横向滚动，增加边缘提示；给父级及子级设置合理的 `min-width: 0`。主导航可使用短标签，低频设置进入弹层。明细表继续在自己的容器内滚动，不让整页变宽。分别验证 320/390/768/1440px，避免用全局隐藏溢出掩盖布局问题。

依据：`public/styles.css:328`、`:517`、`:1302`、`:148`。当前 680px 的尾部修复重点覆盖 Today，Timeline 仍需处理。

### 3. 图表保留实例，让变化连续

`renderChart()` 每次销毁并创建 Chart.js，图例也会重建。用户切换时间范围、单位、主题或刷新数据时，缺少连续的变化，已隐藏系列的选择也可能丢失。

保留实例并更新数据与 options；按厂商名/模型名保存显隐状态。初次加载使用短入场动画，筛选时平滑过渡，主题变化不重播曲线。增加日期垂线、按当前单位排序的 tooltip，以及选中曲线突出效果。

模型排名目前在 Token 模式仍按 cost 选择前八，应按当前单位排名；未使用模型默认不占图例。日统计可采用直线或低平滑度，避免图形暗示未观测的中间数据。Canvas 字体使用解析后的实际字体值。

依据：`public/app.js:287`、`:336`、`:350`、`:412`、`:493`。

### 4. 指标卡更统一，金额与单位更清楚

Timeline 第四张卡固定强调 Gemini，在其他 Agent 筛选中也存在。建议换为通用指标“活跃工程 / 活跃天数 / 日均等值估算”之一，把 Gemini 专属统计放入来源卡。

避免大数字同时显示 `4.80B (48.0亿)`、`434.0M ($105.80)` 等混合格式。主行显示一个核心数值，单位和次级金额放在辅助行；统一数字宽度、精度和对齐。数字更新从上次显示值过渡到新值，保留真实零值与未知值的区别。

建议卡片圆角约 12px，间距 16–24px，主要数字 28–36px，正文 13–14px。主要数值保持高对比；厂商颜色只用于来源标识与曲线，状态颜色保留语义。

依据：`public/index.html:451`、`public/app.js:217`、`:245`。

### 5. 明细表与工程列表控制长度

当前数据下 Timeline 的完整截图约 7714px 高，Projects 更长。大量历史明细会降低总览与比较效率。

明细默认显示 20–30 行，提供分页和明确的总条数；保留搜索、排序和日期筛选，数字列右对齐，可设置表头在明细滚动区域内固定。工程页默认展示重点工程与紧凑列表，详情在原位展开或侧栏查看。

搜索、排序时尽量复用节点；只对可见项做短位移动画。大量工程和图片采用分页或渐进加载，避免一整屏依次延迟入场。

依据：`public/app.js:956`、`:1001`、`:1266`。`renderAll()` 仍会重绘隐藏的 Timeline，应只更新当前可见视图，切回时再补齐。

### 6. 完整的加载与数据状态

当前首屏包含写死的历史数量；刷新按钮添加 `loading` 类，但样式未定义对应旋转反馈。页面绿色状态点持续脉冲、“实时运行中”固定显示，代码中未发现自动轮询。应避免把一次请求成功显示成持续实时连接。

首次加载使用固定高度骨架与 `—`，已有数据刷新时保留界面，在刷新按钮和状态条中反馈。成功后只短暂提示；错误时保留旧数据并标记“显示上次成功数据”。区分最后拉取时间与日志覆盖时间。

快速切换 Agent/计价使用 AbortController 或请求序号，防止旧响应覆盖新选择。为无日志、无搜索结果、无图片、图片加载失败提供不同说明及“清除筛选 / 重试”等恢复入口。

依据：`public/app.js:118`、`:907`、`public/index.html:107`、`:112`、`:132`。

### 7. 详情展开、价目面板与画廊灯箱

当前视图和工程详情主要通过 `display` 或类名直接切换。价目面板是居中 modal；可评估改为右侧详情面板，将搜索与价格表留在同一上下文。

图片点击实际使用 `window.open()` 打开新标签页，尚无单图灯箱。建议实现缩略图到大图的连续过渡、上一张/下一张、缩放与 Prompt 详情，另保留“打开原图”。关闭后恢复列表位置与焦点。

弹层统一处理 Escape、标题关联、焦点范围、焦点恢复和背景滚动；进入与退出都应有过渡。工程卡使用 `aria-expanded` 和 `aria-controls`。

依据：`public/app.js:941`、`:1130`、`:1176`、`:1291`、`:1551`；`public/index.html:772`。

### 8. 主题与样式收拢

现有 CSS 已超过 3600 行，后半段大量组件级浅色覆盖，另有重复 `modalFadeIn`。末尾 `.glow-bg { opacity: 0.025; }` 已覆盖前面的辉光强度，当前视觉并没有早期样式声明看起来那么强。

建立 surface、text、border、shadow、radius、spacing 和 motion token，收拢重复主题分支，替换组件中的硬编码深色。浅色依靠边界与轻阴影建立层级，深色主要靠表面亮度差。把 `transition: all` 改成实际变化属性，避免无意动画。

依据：`public/styles.css:2789`、`:3426`、`:3616`。

## 建议加入的动效

以下时长为初始调校值，需结合设备与实际交互调整。

| 动效 | 建议效果 | 时长 | 触发范围 |
| --- | --- | --- | --- |
| 主导航选中态 | 背景块或指示条平滑滑到目标 | 180–220ms | 用户切换页签 |
| 视图切换 | 淡入 + 4–6px 位移 | 140–180ms | 新显示面板 |
| 指标更新 | 从旧值递增/递减到新值，保持单位稳定 | 350–450ms | 数据或范围变化；后台更新可简化 |
| 图表更新 | 曲线原位过渡，保持来源显隐 | 200–350ms | 改日期、单位或来源 |
| 卡片 hover | 1–2px 浮起 + 边框微亮 | 160–200ms | 可交互卡片；避免暗示普通 KPI 可点击 |
| 详情展开 | 内容区域高度过渡 + 箭头旋转 | 180–220ms | 工程详情 |
| 侧栏 | 轻水平位移 + 遮罩淡入，退出更快 | 220–260ms / 120–160ms | 价目、图表设置、工程明细 |
| 图片预览 | 缩略图与大图位置/尺寸连续变换 | 180–240ms | 图片灯箱 |
| 首次加载 | 稳定骨架 + 内容淡入 | 单次 | 页面首载，保留内容尺寸 |

统一缓动可从 `cubic-bezier(.22, 1, .36, 1)` 开始。优先动画 `transform` 与 `opacity`。首屏轻错峰可控制在 30–40ms；刷新时不重播全部入场。

已有 CSS `prefers-reduced-motion` 保留，同时让 JavaScript 和 Chart.js 遵守用户减少动画的偏好。页面不可见时停止不必要的持续动画。

## 落地顺序

1. 修复手机溢出，压缩顶部控件，日期范围前置，统一 KPI 与图表设置入口。
2. 改为保留图表实例，完善请求顺序、刷新反馈、加载/错误状态与来源显隐。
3. 添加导航、数值、图表、工程详情动效，再完善价目侧栏和图片灯箱。
4. 收拢主题 token，缩短大列表，检查明暗主题、手机、键盘与减少动画模式。

前端保持现有原生 JS + Chart.js 即可；这些优化不要求迁移 React，也不要求引入大型动效库。业务页面实际实施时需再验证数据口径、筛选和图表交互；本次浏览器审查未发现页面脚本异常，但不等同完整业务回归测试。
